# Ingestion and revision

The coordinator handles storage, references, coverage, releases and views. Codex supplies substantive understanding. All MCP calls wrap the input in `request`. `kb_status` reports the engine and corpus paths; the CLI fallback is `node <engine>/dist/cli.js COMMAND --input REQUEST.json`. Use the current project identity, never another project's identity to bypass a denial. Load [books.md](books.md) for books/papers and [video.md](video.md) for recorded teaching; a mixed course uses both. They share this publication workflow.

1. Inspect the requested material and the bound scope. Use `kb_maintain` action `configure` to register a new module/domain when the task authorizes that research scope. Preserve distinct meanings and evidence families. Do not ingest an entire legacy folder merely because a source refers to it.
2. `kb_ingest`: supply `paths`, `module`, `domains`, a stable `idempotency_key`, and `authorization` quoting or accurately summarizing the actual task. Save the returned job ID.
3. `kb_job` action `convert` extracts text and assets. Read each coverage unit with `kb_read {kind:"unit",job_id,unit_id}`; follow `next_offset` until null. This returns locators, text and visual images through MCP without requiring shell access. Inspect relevant page images, diagrams and frames; conversion is not reading. Local originals remain available for deeper inspection. Media uses the video guide's whole-job paid preflight and API decoders. Use the source tools for native frames, crops, reviewed reading copies and source reviews. New evidence reopens the affected job stages.
4. Reconstruct sections in manageable batches, then the whole source's argument. Use `kb_job` action `submit` with `receipt: {step_id, stage, summary, coverage:[{unit_id,status,reason?}]}`. Partial receipts save progress. Mark a unit complete only after doing that stage's work; exclusions need real reasons. Preserve consequential unresolved visual or interpretive gaps.
5. Author meaning through `kb_propose` with `proposal`. Get its contract using `kb_read {kind:"schema",name:"proposal"}` and record payload contracts using `name:"record"`. Copies are in the engine's `contracts/schemas/` directory. Use local names via `{local_ref: "name"}` within a batch. IDs, timestamps, hashes, revisions and default unassessed confidence are generated. Use `existing_ref` to revise a published record, and `replace:true` to explicitly replace an uncommitted batch with the same proposal ID. Do not manufacture confidence scores.

The job proceeds through reconstruct, integrate, discover, reweave, compile, check and publish. Follow its returned instruction and actual remaining work. Integration compares definitions, applicability, evidence independence and disagreements with permitted knowledge. Produce coherent explanations of why and how, appropriate primers, worked examples or teaching records, and evidence-grounded questions. Preserve boundary cases and failed preconditions. Use pattern mechanisms and `exemplifies` when justified; do not force cross-domain correspondences.

Discovery searches by mechanism, purpose and constraints. A useful candidate names its premises, differences, limits, expected value and next test. Returning none is valid: discovery receipts require `stopping_reason` and `unfinished`. There are no page, link or probe quotas.

Reweaving revisits affected prose, prerequisites, examples, primers, assessments, summaries and questions. New jobs use workflow version 2. Their next-step response includes a `reweave` plan covering existing pending impacts, exact input dependencies and new, changed or retired material relationships. Read those targets and the new source before deciding what changes. Revise the reasoning, not just backlinks; preserve contrary evidence and separate source accounts.

Submit reweave receipts with `resolutions:[{record_ref,decision:"revised"|"reaffirmed"|"pending",rationale}]`. Revised or reaffirmed means a new canonical revision is staged through `kb_propose`; a receipt alone is insufficient. A pending decision explicitly preserves unfinished assessment. Partial decisions keep the stage open until all returned targets have a decision. Out-of-scope dependents remain pending. If later staged meaning changes, affected decisions expire and must be reconsidered before publication. Do not clear a queue by calling unresolved work reaffirmed.

Check receipts use `capability: checked | unresolved_failures | not_assessed`. Structural validity is not independent application evidence. Unresolved failures block advancement; unavailable independent checks remain explicitly unassessed. Test important new applications and tempting invalid transfers. Do not expose private grading cases to the ingestion context or relabel a repaired regression case as held-out.

For workflow version 2, include `understanding_change:{added:[],revised_refs:[],unresolved:[],checks:[]}` in the check receipt. Explain the new supported understanding, changed exact revisions, open issues and checks actually performed. If `added` is empty, supply `no_new_supported_understanding` with the reason; redundancy is a valid outcome. `capability:"checked"` requires recorded checks. Publication retains this report and pending reassessments, including when recovering an interrupted commit. Legacy jobs retain their original receipt contract.

Navigation uses existing summaries, definitions and learning/question fields. Where those are insufficient, author `extensions.navigation:{interface_version:"1.0.0",summary:"..."}` on the owning record. A missing summary stays explicit; a title is not a substitute. Revise summaries alongside their explanations and check any material source qualification before deriving a summary from an earlier summary.

`kb_change` action `preview` shows staged meaning. Publish within existing task authorization using `kb_job` action `publish`; no extra permission ceremony for an already authorized ingestion. Then `kb_maintain` action `reindex` and `verify`. Report canonical publication separately from graph/search readiness. On `REVISION_CONFLICT`, inspect intervening changes, use job `rebase`, then redo affected reweaving/checks. Never overwrite the winning release.

End with what the source added or changed, consequential disagreements and gaps, capability checks actually run, and the library/release location. Do not claim that retrieval retrained the model or established mastery.
