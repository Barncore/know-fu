# Operations

Whole-library `verify`, `export` and `formats` require unrestricted read access to every module. `restore` also requires corpus-wide write authority. Scoped callers receive `SCOPE_DENIED`; these commands do not produce partial backups. Exact reads expose only committed release ancestry. Ordinary edits preserve archive, withdrawal and supersession state; lifecycle execution and purge resumption recheck the caller's current permissions.

Evaluations freeze cases, model, release, scope, conditions and budget settings before running. Version 3 additionally freezes the executable implementation and supports interactive reading. A change requires a new run. Grading must match the applicable structured contract; malformed responses leave the run incomplete, with raw responses and immutable attempts retained. Completed attempts are reused only if their receipts match. Version 2 preserves the fixed-packet comparison; older legacy reports remain inspectable by their authorized owner.

Start with the bundled [package README](../../../README.md), [schema and layout](../../../docs/architecture.md), and [setup guide](../../../docs/setup.md). `kb_status` reports the separate engine and corpus locations; the README at that engine path contains deployment evidence and known limits. Use regular FalkorDB through the configured managed-WSL or external-server deployment; no silent graph SQLite or FalkorDBLite fallback. The setup guide distinguishes tested deployments from configurable alternatives. Local installation paths are configuration, not a portable skill dependency.

Use `kb_status`, `kb_maintain reindex` and `verify`. Graph start/status/restart: engine `scripts/graph-service.ps1 -Action start|status|restart`. Canonical files remain authoritative when a view is unavailable. Do not rewrite them to make an index appear healthy.

`kb_maintain configure` accepts a `module {module_id,title,description}`, `domains [{domain_id,title}]`, optional `binding {project_id,read_modules,write_modules}`, optional `dimensions {name:{type,unit}}`, and actual task `authorization`. The owning project must have all modules writable. Bind new Codex projects only when requested; cross-harness integration is deferred. A condition dimension's meaning is immutable: use a new name for changed units/semantics.

Archive/unarchive changes navigation; withdrawal blocks reliance; reinstatement needs a current assessment. `kb_lifecycle` mode `plan` accepts `action`, exact `targets` and `reason`. Inspect dependents, then execute the returned `plan_id` using actual user authorization `{action,targets,user_instruction}`. Purge requires explicit deletion authorization and removes the previewed content and derivatives, including affected managed backups. It cannot erase external backups or provider copies. Partial failure blocks affected access; retry the same plan after resolving the failure. Keep the independent deletion ledger under the configured state directory's `ledgers/` (`KB_STATE_DIR`, legacy default engine `.runtime/ledgers`) backed up separately. A missing/stale ledger blocks restored service.

Supersession and scoped concept merge: `kb_maintain plan_meaning`, with `kind: supersede|merge_concepts`, `target`, `replacement`, `reason`; then `execute_meaning` with `plan_id`, `plan_hash`, `authorization`. Original sources and author-specific accounts remain; supersession is for justified interpretations. Reassess affected dependents instead of silently rewriting their meaning.

`export` creates a portable full bundle inside the corpus; `restore` accepts `bundle_path,target` and requires the matching independent deletion ledger. `import` accepts `bundle_path,module,domains` for an explicitly selected foreign corpus. Imports preserve exact original revision identities in an origin map; historical revisions become archived records rather than collapsing into a latest revision. No automatic migration of existing research folders.

`formats` emits JSONL, citation CSV and Mermaid. Generated wiki edits are detected: `wiki_edit` with `record_ref` returns proposed prose for review and normal publication. `preview_bulk`/`execute_bulk` stage an exact reviewed proposal. Never bulk-accept dubious meaning to clear a queue.

`kb_evaluate prepare` takes source-grounded `cases`, `model`, optional `conditions` and `options`. Cases include `case_id,prompt,query,rubric,source_refs,source_grounding,held_out`, with optional `purpose`. `run` and `report` take `run_id`. Fixed conditions are `no_kb`, `source_passages`, `full_kb` and `prose_and_passages`; interactive conditions are `progressive_graph` and `progressive_prose`. Both progressive conditions retain material-context checks. `options.repetitions` measures variability; repeats of one case are not independent questions.

Version 3 options include `budget:{tool_calls,rendered_characters,input_tokens}`. Tool calls, delivered evidence and wall time are bounded. Actual cumulative model input, including repeated context, is measured after completion; `input_tokens` is a comparison ceiling, not a pre-call hard stop. Report exceeded or unmeasured budgets. Preserve separate correctness, completeness, decisive conditions, citation support, teaching, synthesis, inference and gap-recognition grades. Inspect decisive failures rather than average them away.

Fresh evaluation sessions have denied native file/network access and, for interactive conditions, only a fixed-scope, pinned-release read-only MCP reader. They cannot read guides, unpublished units, hidden rubrics or other conditions. An isolation probe must match the current policy/code fingerprint before a version 3 run. These sessions measure the constrained text-reading path; ordinary source-image inspection remains a separate acceptance check.

Evaluation sends selected evidence to the configured Codex service using its normal sign-in. Establish authorization for that material and destination; never infer private-data permission from a build request or copy authentication files. Additional original passages (`grading_refs`) or public extracts (`grading_evidence`) require `options.grading_data_authorization`, binding the destination, actual authorization basis, statement, source refs and exact extract hashes. This is an explicit per-run payload boundary, not automatic access to every source. Raw usage, trajectories and outcomes remain private outside research views. Cases exposed for repair become regressions; do not relabel them held-out.

Paid transcription configuration uses `transcription.models[]`: `id`, HTTPS `endpoint`, `model`, `key_env`, `estimated_cost_per_minute`, `currency`, optional `response_format`, `timestamp_granularities`, `prompt`. See the engine's `config/transcription.example.json` and video guide. `media_plan` makes no API requests. All media and decoders share durable job reservations; the allowance cannot guarantee the provider's final bill. Never infer dollars from subscription tokens. Unknown paid outcomes must be reconciled before resubmission. Cancel/resume retains coverage and provider receipts; do not start a duplicate job to bypass an unresolved charge.
