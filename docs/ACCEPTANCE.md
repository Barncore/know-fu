# Capability acceptance contract

This contract was set on 4 October 2026 before outcomes from the progressive-reading comparison. It implements the [north star](NORTH_STAR.md); results belong in [VALIDATION.md](VALIDATION.md). Private case wording, rubrics, model traces and canonical snapshots stay outside the public package.

## Behaviors and evidence

| Use | Required behavior | Decisive failure |
|---|---|---|
| Explain | Give a connected mechanism, the relevant unit and a condition that changes the explanation | Conflate different statistical questions or erase a precondition |
| Teach | Start from prerequisites, work a concrete case, address a tempting misunderstanding and check understanding | Teach omnibus rejection as every pair differing, or non-rejection as equivalence |
| Apply | Execute the decision procedure on unfamiliar inputs and explain its limits | Wrong rejection set, incorrect stopping rule or invalid independent sample size |
| Compare | Preserve both positions and compare definitions, evidence and scope | Choose a winner using incompatible metrics or unsupported error-rate claims |
| Invent | Combine supported mechanisms with an explicit new inferential step and a discriminating test | Attribute the proposed transfer to the source as an established result |
| Synthesize | Cover the decision pipeline, important branches, exceptions and evidence limits | A coherent overview that silently loses a decisive condition |
| Investigate | Identify the missing evidence that could change the decision and prioritise a feasible next check | Fabricate current evidence or treat a sparse graph as a valuable gap |
| Learn cumulatively | Later complementary and qualifying sources alter affected procedures, teaching and questions while preserving source accounts | Only append new records, or silently rewrite an earlier author's position |
| Preserve knowledge | Earlier unaffected cases remain usable after reweaving | Lose a correct stopping rule, exact-source discrepancy or access restriction |

## Comparison design

The preserved Demšar pilot release has 109 canonical records. Hashes of every exact record and body are frozen before new case design. Its six original cases are now exposed engineering regressions. Separate acceptance prompts are authored after that freeze, with source-grounded rubrics withheld from the solver and corpus. The source-reading coordinator designs and reviews cases; this is not an independent blind benchmark.

For access structure, keep the canonical release and page bodies identical. Compare the original fixed full packet with progressive reading using and omitting optional graph exploration. Both progressive routes must retain canonical material-context checks. Use the same configured model, reasoning effort, word limit and cumulative input ceiling. Record measured total input, cached input, output, latency, delivered evidence, selected summaries, actual account/section reads and unmet requirements. The input ceiling is checked after completion; it is not a guaranteed hard token cutoff.

Seven task groups cover the uses above. Repeat the decisive application and exception cases to expose variability; repetitions are not independent tasks. Source-grounded grading reports each quality dimension separately. Review every decisive failure, source/rubric dispute and any material difference between conditions against the original evidence. A favorable aggregate cannot cancel a missed condition.

Adoption requires no unresolved decisive factual or condition failure, adequate completeness for every task group, and useful reading efficiency on narrow tasks. Specifically, the candidate should reduce measured input against the fixed packet on at least two narrow task groups without losing their quality requirements. Broad synthesis may cost more; report that tradeoff rather than excluding it. A result outside the shared input ceiling is descriptive evidence, not a matched-budget win. Failure of an optional graph advantage is not failure of the library architecture.

For cumulative knowledge, preserve the foundational source; add Bengio and Grandvalet's cross-validation variance account, then Benavoli, Corani and Mangili's qualification of mean-rank post-hoc testing. Read each original before integrating it. Compare frozen before/after tasks about those boundaries and an unfamiliar application, with original-passages-only and no-library controls where informative. Repeat unaffected procedures. The result must identify which understanding changed, which earlier explanation or teaching route was revised, and what remains unknown. A small public-paper demonstration does not establish domain mastery or production readiness for arbitrary books.

## Release checks

Required engineering checks cover scoped metadata, exact history, withdrawal propagation, pending reassessment, low-ranked caveats, stable section boundaries, stale projections, changed staging, publication recovery, reading budgets, isolation and immutable evaluation resumption. Confirm real installed MCP discovery, selected reading, source-image access and guides. Verify the owned plugin and packaged contracts, review staged paths/content for private material, then publish the approved release. Production corpus binding and large historical migrations remain separate work.
