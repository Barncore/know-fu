# Capability acceptance contract

This contract was written on 4 October 2026, before any results from the progressive-reading comparison came in. That timing is the point: the bar was set before anyone knew whether the new route would clear it. It turns the [north star](NORTH_STAR.md) into things you can check. Results belong in [VALIDATION.md](VALIDATION.md). Private case wording, rubrics, model traces and canonical snapshots stay out of the public package.

## What "more capable" has to look like

| Use | What a good answer does | What sinks it |
|---|---|---|
| Explain | Gives a connected mechanism, the relevant unit, and a condition that changes the explanation | Conflating different statistical questions, or erasing a precondition |
| Teach | Starts from prerequisites, works a concrete case, tackles a tempting misunderstanding, checks understanding | Teaching that an omnibus rejection means every pair differs, or that non-rejection means equivalence |
| Apply | Runs the decision procedure on unfamiliar inputs and explains its limits | A wrong rejection set, an incorrect stopping rule, or an invalid independent sample size |
| Compare | Keeps both positions, and compares definitions, evidence and scope | Choosing a winner with incompatible metrics or unsupported error-rate claims |
| Invent | Combines supported mechanisms with an explicit new inferential step and a test that could tell | Passing off the proposed transfer as an established result from the source |
| Synthesize | Covers the decision pipeline, the important branches, exceptions and evidence limits | A coherent overview that silently drops a decisive condition |
| Investigate | Finds the missing evidence that could change the decision, and prioritizes a feasible next check | Inventing current evidence, or treating a sparse graph as a valuable gap |
| Learn cumulatively | Later complementary and qualifying sources change the affected procedures, teaching and questions, while keeping each source's own account | Only appending new records, or quietly rewriting an earlier author's position |
| Preserve knowledge | Earlier unaffected cases still work after reweaving | Losing a correct stopping rule, an exact-source discrepancy or an access restriction |

## How the comparison was designed

The preserved Demšar pilot release has 109 canonical records. The hashes of every exact record and body were frozen before any new cases were designed. Its six original cases have since become exposed engineering regressions. Separate acceptance prompts were written after that freeze, with rubrics grounded in the sources and kept away from both the solver and the library. One honest caveat: the coordinator who read the sources also designed and reviewed the cases, so this isn't an independent blind benchmark.

For access structure, the canonical release and page bodies stay identical across conditions. The original fixed full packet goes up against progressive reading, with and without optional graph exploration, and both progressive routes keep the canonical material-context checks. Every condition uses the same configured model, reasoning effort, word limit and cumulative input ceiling. Each run records measured total input, cached input, output, latency, delivered evidence, selected summaries, actual account and section reads, and unmet requirements. The input ceiling is checked after completion, so it isn't a hard token cutoff.

Seven task groups cover the uses above. The decisive application and exception cases get repeated to expose variability, but repeats aren't independent tasks. Grading against the sources reports each quality dimension on its own. Every decisive failure, every dispute over a source or rubric, and every material difference between conditions is reviewed against the original evidence. A nice aggregate can't cancel out a missed condition.

To become the default, a route needs three things: no unresolved decisive factual or condition failure, adequate completeness for every task group, and useful reading efficiency on narrow tasks. Concretely, it has to use less measured input than the fixed packet on at least two narrow task groups without losing their quality requirements. Broad synthesis is allowed to cost more, as long as that trade-off is reported instead of hidden. A result over the shared input ceiling is descriptive evidence, not a matched-budget win. And if the optional graph shows no advantage, that's not a failure of the library architecture.

For cumulative knowledge: keep the foundational source, add Bengio and Grandvalet's account of cross-validation variance, then Benavoli, Corani and Mangili's qualification of mean-rank post-hoc testing, reading each original before integrating it. Compare frozen before-and-after tasks about those boundaries and an unfamiliar application, with original-passages-only and no-library controls where they help, and repeat unaffected procedures. The result has to show which understanding changed, which earlier explanation or teaching route was revised, and what's still unknown. A small demonstration on public papers doesn't prove domain mastery, or readiness to ingest arbitrary books in production.

## Release checks

The engineering checks cover scoped metadata, exact history, withdrawal propagation, pending reassessment, low-ranked caveats, stable section boundaries, stale views, changed staging, publication recovery, reading budgets, isolation and immutable resumption of evaluations. Then confirm real installed MCP discovery, selected reading, access to source images, and the guides. Verify the owned plugin and packaged contracts, review staged paths and content for private material, and publish the approved release. Binding the production library and large historical migrations are separate jobs.

A footnote for 1.2.0: `kb_recall` was judged against this contract's cases with a blind A/B comparison rather than the version 3 evaluator. [VALIDATION.md](VALIDATION.md) explains how, and why.
